# Learning Path Generator（学习路线生成器）

从「用户提供的教程链接 + 官方文档」生成一份**自包含、零链接、按认知规律编排**的学习路线。

方法论源自一次完整的 Go 学习路线共建过程：菜鸟教程作知识底座 → 官方教程（入门/模块/泛型/数据库/Web 框架）内容融入正文 → 覆盖度审查补缺口 → 一致性审查修复 5 处偏离。以下规则全部来自该过程中用户明确提出的偏好与踩过的坑。

## 核心原则（不可违反）

1. **不脑补**：所有知识点必须来自实际抓取到的教程/文档内容。抓不到就明确告知用户，绝不凭记忆编造目录或内容
2. **不照搬**：源教程只作知识底座，阶段结构按认知规律重排（先会用 → 再理解 → 后工程化 → 终于实战），不逐章复刻源目录
3. **不预设背景**：除非用户明确要求，不引入其他语言/技术的对照（如用户学 Go 时明确拒绝 Java 对照）
4. **零链接**：正文不放任何 URL；知识点、代码示例、被引用的内容全部提炼内嵌，读者从头读到尾不需要中途查外部资料
5. **融入而非并列**：官方教程内容编进各阶段正文（不设"官方教程补充"式独立板块）；教程中"引用了但没展开"的东西直接补全
6. **先审查后修改**：完成后先输出只读审查报告（分级列出问题），经用户确认再动文件

## 工作流程

### 第 1 步：需求确认
开始前必须向用户确认：
- 目标技术 + 用户提供的资料链接（教程站/官方文档）
- 基础水平（零基础？）与目标深度（学完大部分内容？达到初步工程实践能力？）
- 每天可投入时间 / 期望总时长

### 第 2 步：素材抓取与核实
- 用 curl 逐个验证用户链接：跟随重定向（-L）、验证 HTTP 200、必要时去掉 `.html` 后缀重试
- 提取教程完整目录（全部章节标题与对应页面），再逐页抓正文
- 分页教程要发现并抓全所有子页（在 HTML 中 grep 下一页/同前缀链接）
- 任何链接抓取失败：如实报告并请用户提供替代来源
- 具体命令、HTML→文本提取脚本、已验证站点技巧见 [references/source-extraction.md](references/source-extraction.md)

### 第 3 步：结构设计
- 按认知规律把知识点重排为 6~10 个递进阶段（参考范式：环境工具链 → 基础语法 → 流程控制与函数 → 数据容器 → 类型系统/抽象 → 错误处理与工程规范 → 核心特性（并发等）→ 文件/数据库/Web 与毕业实战）
- 每个阶段固定结构：**目标 → 知识提炼（含可运行代码示例）→ 练习（勾选清单）→ 过关自检（能回答才进入下一阶段）**
- 高频考点/核心特性在标题打标（⚠ 重点 / ⭐ 核心）
- 收尾设计：2~3 个融合全部所学的毕业项目（至少一个衔接真实工程形态）
- 伏笔技法：前阶段埋"后面会兑现"的钩子（如 defer → 文件关闭/解锁），后阶段必须真正兑现

### 第 4 步：内容提炼
- 每个知识点 = 概念说明 + 最小可运行代码 + 易错点/记忆口诀
- 源教程只有提法没有内容的，用官方文档补全；官方文档"提到但没给代码"的，写出代码
- 命令、类型、API 用速查表呈现
- 每阶段末尾的练习只用已教内容（新知识点落地即配练习）

### 第 5 步：一致性自审（交付前必做）
对照 [references/quality-checklist.md](references/quality-checklist.md) 全量检查，问题按 🔴 结构硬伤 / 🟡 执行偏差 / 🟢 小瑕疵 分级输出审查报告；用户确认后修复，修复后复查一次。

### 第 6 步：交付格式
- 单个 Markdown 文件（`XX学习路线.md`）保存到用户工作目录
- 头部声明（总时长、版本基线、内容构成）必须与实际内容一致，内容大改后回头同步声明
- 文末固定三件套：
  - **学习原则**（含"两遍学习法"：第一遍走路线做项目，第二遍精读官方惯用法指南）
  - **附录**：延伸资料表（仅"名字 + 定位"，不放链接）
  - **后续深入主题**：超出目标范围的进阶内容全部锁在这里

## 快速自查口诀

> 顺序不超前 · 练习不超纲 · 承诺必兑现 · 自检全覆盖
> 时长符体量 · 版本要标明 · 正文零链接 · 进阶锁附录
